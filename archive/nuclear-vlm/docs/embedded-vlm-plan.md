# 組み込みVLM移行計画

## 目標

核医学PDF登録で使うQwen3-VL 2Bを、利用者がOllamaを別途導入しなくても
Electron版RadExam内でローカル実行できるようにする。ネットワークへ問題PDFや
抽出画像を送信せず、VLMが使えない場合は既存のルールベース処理を継続する。

## 現在の位置付け

核医学PDF登録の標準方式は、個別図抽出ではなく巻末図ページ参照方式へ変更した。
VLMは比較検証用に残している従来の個別図抽出方式でのみ使用する。巻末図ページ参照方式では
モデルの有無にかかわらず、問題文中の「別紙 No.」と巻末図ページの「No.」見出しを対応付ける。問題文・選択肢のページは参照対象にしない。

## 採用構成

- Electronのメインプロセスが`llama-server`をサイドカーとして起動する。
- Next.js APIはVLMプロバイダーを通じてOllamaまたは組み込みサイドカーを呼ぶ。
- サイドカーはlocalhostだけで待ち受ける。
- モデルはQwen3-VL 2B Instructの量子化GGUFを標準とする。
- モデル本体とmultimodal projectorは、同梱または初回取得後にユーザーデータ領域へ置く。

## フェーズ

### 1. 推論バックエンドの分離（実装済み）

- `auto`、`embedded`、`ollama`のプロバイダー選択
- Ollama APIとOpenAI互換マルチモーダルAPIの共通化
- JSON Schema出力、thinking無効化、既存の応答検証を共通利用
- 管理画面への実行方式表示

### 2. Electronサイドカー管理（実装済み）

- OS・CPUアーキテクチャ別の`llama-server`探索
- 空きポートでの起動とNext.jsへの接続情報引き渡し
- アプリ終了時のプロセス停止
- 組み込み資産がない場合のOllama継続
- 開発用バンドル検証コマンド

### 3. 配布資産の固定（実装済み）

- llama.cpp b10019を固定
- macOS arm64/x64、Windows x64、Linux x64の公式配布URL・サイズ・SHA-256を固定
- Qwen3-VL 2B Instruct Q4_K_MとQ8_0 projectorの配布元・ライセンス・SHA-256を固定
- 開発時に`npm run vlm:prepare-runtime`で対象ランタイムを検証・展開
- `npm run vlm:verify`で固定リリースとの一致を検証
- Electronの`extraResources`にサイドカー一式を含める

### 4. 初回モデル取得（実装済み）

- アプリ内に2B/4Bモデルの取得・進捗・選択・削除・再起動UIを追加済み
- 取得開始前の空き容量確認と512MiBの安全余裕を追加済み
- 一時停止と`.part`ファイルによる続きからの再開に対応済み
- サイズとSHA-256の検証に成功した場合だけ有効化済み
- 残作業: オフライン配布向けモデル同梱ビルド

### 5. 品質・性能検証

- 難しいページを含む固定評価セットを作る
- 設問割当、図の分割・結合、レジェンド割当を2B Ollama版と比較する
- 各OSで初回起動、連続PDF登録、異常終了、再起動を試験する
- 8GB/16GBメモリ端末で処理時間とメモリ使用量を記録する

## 完了条件

- 新規PCでOllamaなしに核医学PDF登録が完了する。
- PDF画像がlocalhost外へ送信されない。
- モデル欠損・破損・起動失敗時に登録処理全体が停止しない。
- Ollama版と同等以上の固定評価セット結果が得られる。
- 2B/4Bの切替とモデル削除がアプリ内で完結する。
